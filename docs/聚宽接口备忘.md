# 聚宽接口与口径速查表

> **这份文件的用途**：不必再探测一遍。
> 每条都是**实测定案**（有依据、有出处），不是推测。
> 详细推导留在各 loader 的模块 docstring 里（本表「出处」列指向它）—— 那是权威原文，
> 本表只做**索引 + 结论**。
>
> 对应的 QMT 侧速查表在 `assay/qmt/PROBE_FINDINGS.md`。
>
> **想按别的维度查？** 同一批知识有四维索引：[数据字典/](数据字典/README.md) ——
> 按需求 / 按接口 / 按字段 / 按陷阱。本文件是其中「按主题」的那一份。
>
> **纪律**：新结论先写进 loader docstring（挨着代码），再在本表加一行。
> 反过来（只写表不写代码）会让代码与文档分叉。

## 1. 期间口径 —— 单季还是累计

| 字段 | 结论 | 依据 | 出处 |
|---|---|---|---|
| `indicator.roe` | **单季** | 茅台 2023 四期 10.00/7.25/8.07/10.08，相加 35.40 ≈ 年报累计 34.65 | `load_jq_indicator_q.py` |
| `indicator.eps` | **单季** | 四期相加 ≈ 全年 | 同上 |
| `get_fundamentals` 季度财务 | **单季度，不是累计** | 平安银行 2017 四单季 `net_profit` 相加 = 年报，精确相等 | `README.md` §口径与陷阱 |
| `lake.db/fin_income` | **累计**（raw 层） | std 层才转单季，分层各司其职 | `README.md` §单季 |
| `inc_*_year_on_year` | **单季同比** | Q1 反证：Q1 两口径都命中 96.6%，Q2 起分岔（累计 4.4% vs 单季 95.7%） | `load_jq_indicator_q.py` |
| `inc_*_annual` | **口径不明，不要用** | 累计同比/单季同比/累计÷上年年报/三年CAGR 命中率均约 1% | 同上 |

> ★ 这条坑过一次：`indicator.eps` 当累计用会误剔股票。
> 603029 在 2018 累计 EPS Q1 +0.0095 → H1 −0.07 → Q3 −0.05；
> 单季 Q3 = −0.05−(−0.07) = **+0.02 > 0**，聚宽放行；用累计 −0.05 就误剔了。

## 2. 分子分母口径 —— 归母还是全口径

| 字段 | 结论 | 依据 | 出处 |
|---|---|---|---|
| `indicator.roe` 的分母 | **平均净资产 (期初+期末)/2**，不是期末 | 257,525 条全样本：平均 **87.35%** / 期末 41.22% / 期初 40.08%。茅台 2023 逐条对到小数点后四位 | `load_jq_indicator_q.py` |
| `indicator.roe` 单位 | **百分数**（10.00 = 10%）；std 层统一转**小数** | 转换只在 loader 一处做，避免同名不同标尺 | 同上 |
| `inc_net_profit_year_on_year` 分子 | **净利润（全部，含少数股东）** → 与本地归母只对上 28% | 用归母那个字段 `inc_net_profit_to_shareholders_year_on_year` 对上 **94.8%** | 同上 |
| `net_profit_this_year` | **归母**净利润 | 对 `income.np_parent_company_owners` 匹配 99.75%，对 `income.net_profit` 只有 33.2% | `build_canonical_views.py` |
| `total_owner_equities` | **全口径**所有者权益 | ★ 与上一条搭配 = 分子归母、分母全口径，**差约 5% 且完全不报错** | 同上 |
| std 层比率 | 统一存**小数**不是百分数 | 如 `inc_return` 中位约 1%，原版阈值 `between 5 and 100` 要 ÷100 | `红利指数增强.py` |

## 3. 时点语义（as-of）—— 少一个条件就是未来函数

| 项 | 结论 | 依据 | 出处 |
|---|---|---|---|
| 财务 as-of | **双键**：`pub_date`（可见性）+ `report_date` | 单键会漏修订 | `README.md` §as-of |
| 股本变动 | `change_date` = 变动**生效**日；`pub_date` = 公告日 | 复现当时流通市值用 `change_date`；严格防未来函数用 `greatest(change_date, pub_date)`。两个都保留，消费方选 | `load_jq_share_change.py` |
| 分红 | 必须用**公告日**，不能用除权日 | `raw_gbbq` / HF `xdxr` 只有除权日，用了就是未来函数 | `README.md` |
| 选股 vs 过滤的日期 | 聚宽**混用两个日期**：选股用前一交易日、过滤用当日 | `get_fundamentals(q, date=yesterday)` vs `filter_limitup_stock` 用 `get_current_data()` | `backtest_froec.py` |
| `valuation.pb_ratio` | 含 **6.58% 前视**（用了当日未公告的财报） | → 本地自算 pb 更正确 | `load_jq_share_change.py` |
| 买来的 pb/pe | 用最新财报 = **含未来数据** | 本地 `totalmv ÷ fin_visible_at(d)` 更严格 | `README.md` |

## 4. 数值口径分歧（两边都没错，只是定义不同）

| 项 | 结论 | 出处 |
|---|---|---|
| 流通股本**两个口径** | `share_rmb` = 流通**A股**；`share_trade_total` = 流通股**总计**（可能含 B/H 股）。A+B 或 A+H 的公司两者不等 | `load_jq_share_change.py` |
| tdx vs 聚宽 3.75% 差异 | **很可能就是上面那个口径差** —— A 股策略应以 `share_rmb` 为准 | 同上 |
| `valuation.capitalization`（总股本） | **tdx 更准**：用 `balance.paidin_capital` 裁判，本地符合会计口径 70.6%、JQ 仅 29.4% | 同上 |
| 股本变动生效时点 | **tdx 比聚宽晚 1 个交易日**，边界日选股会差一只，**本地无法消除** | `backtest_froec.py`（v0b 复现 9/10，唯一差异即此项） |
| `bonus_ratio_rmb` | 是**每 10 股派息**，要 ÷10 | `assay/assay/feed.py` |
| `volume` 单位 | 是**股 × 100**；成交量约束一律用 `amount`（元） | 同上 |

## 5. 接口本身的陷阱

| 项 | 结论 | 出处 |
|---|---|---|
| 财务必须过滤 `report_type = 0` | 不过滤会混入母公司报表：平安银行 2015 年报合并营收 961.6 亿 vs 母公司 734.1 亿，净利差 10% | `README.md` |
| 财务起点 **≥ 2003** | 1989–2002 的 `pub_date` 占位率 0.38~1.00，是假值 | 同上 |
| `get_all_securities` | 必须 `date=None`，否则**漏退市股** | 同上 |
| `PEG` 因子 | 盈利增长为负时返回 **NaN**，不是负值 | 同上 |
| `get_fundamentals(statDate=)` | 同一 `(code, statDate)` 只返回一条，**没有修订史**。修订史走 `finance.STK_*` | `load_jq_indicator_q.py` |
| 业绩快报 | 聚宽 `pub_date` **99.8% 对齐定期报告**（快报仅 11 行）→ 聚宽自己也不用快报，我们跟它一致才能对标。快报单独落 `std/fin_express.parquet`，**不与主表混用同一 as-of** | `load_jq_express.py` |
| 后复权因子 | 首日=1、单调不减 → 新增分红**不改历史因子**（4 只票实测下降次数 0） | `README.md` |
| 前复权 qfq | **不能做特征**：基准是"今天"，每次新事件重算全历史 | 同上 |
| `adjust_factor` 异常 | 72,195 条负值/天文数字，集中在 **43 个 B 股**（sh90*/sz20*）+ 2 基金；A 股策略无影响 | 同上 |
| HF `tdx_financial.parquet` | **当前不可用**：586 列缺股票代码列（列名整体错位一格） | 同上 |

## 6. 行业分类版本

| 项 | 结论 |
|---|---|
| 聚宽 `sw_l1_name` | 申万 **2014 版**，带 `I` 后缀（`钢铁I`/`采掘I`/`交运设备I`/`金融服务I`） |

详见 `assay/qmt/_tpl/froec.py` 的 `INDUSTRY_FILTER` 注释。
