## 🔴 先说清这份文档给的是什么

**给的是「自建因子池的实现规格」，不是「聚宽那个因子的复刻」。** 三档可信度，
每条都标了 —— 把它们混为一谈会得到一批「看着正常的错值」：

| 标记 | 含义 | 条数 |
|---|---|---:|
| ✅✅ | **逐只实测定案**，与聚宽精确一致（出处 [jqfactor-口径.md](jqfactor-口径.md)） | 4 |
| ✅ | 公式是**行业标准 / 会计定义**，没有歧义；与聚宽**大概率**一致但未逐个验证 | 228 |
| ⚠️ | **自建定义** —— 数据齐、但聚宽口径未知。算出来是个**有意义的因子，但不是聚宽那个** | 42 |
| ❌ | 数据不存在，给不出 | 4 |

🔴 **285 行只有 278 个不同名字**：`动量因子`×2 / `市净率因子`×2 / `市场杠杆`×2 / `成长因子`×2 / `流动性因子`×3 / `计算VMACD因子的中间变量`×2。
多半是聚宽同名不同 factor code（窗口或口径不同），**光看中文名分不出来** —— 落地前要拿到各自的 code。

## 记号

```
行情（全部后复权）   C = close_hfq        H = high × hfq_factor
                    L = low  × hfq_factor  O = open × hfq_factor
                    PC = preclose × hfq_factor
                    R = C / C₋₁ − 1        V = volume_shares   A = amount
                    TO = turnover（**百分数**：0.0883 = 0.0883%）
算子   MA(x,n) 简单均   EMA(x,n) 指数均 α=2/(n+1)   STD/VAR/SKEW/KURT 滚动统计
       MAD(x,n) 平均【绝对】偏差   SUM/Σₙ 滚动求和   MIN/MAX 滚动极值
       x₋ₙ 前 n 个交易日的值        rank_cs 当日横截面排名
财务   x_q  单季 = 当期累计 − 上期累计（Q1 直接取累计）
       TTM(x) = 最近 4 个单季之和
       x₋₄期 = 上一年同期（用于同比）
       as-of = 取 pub_date ≤ 当日的最新一期，🔴 ORDER BY report_date DESC, pub_date DESC
```

🔴 **三条会静默出错的**：

1. **复权口径不一致** —— `panel` 里 `open/high/low/preclose/close_bfq` 是**不复权**，只有
   `close_hfq`/`hfq_factor` 是后复权。技术指标一律用后复权，`H = high × hfq_factor`。
   同一行混用不报错，只是价格错一个复权因子（老股能差几十倍）。
2. **`turnover` 是百分数**，与同一张面板里的 `roe_ttm` 等**小数**比率混着放，当小数用差 100 倍。
3. **同比的分母取原值，不取 `abs`** —— 连亏两年时负÷负=正，这是实测定案的（见下）。

## ❌ 无法实现（4 个）

| 因子 | 要算它需要什么 | 为什么本地给不出 |
|---|---|---|
| 预期短期盈利增长率 | 未来 1 年一致预期净利 / 当前 TTM 净利 − 1 | 需**卖方分析师一致预期**（朝阳永续 / Wind consensus） |
| 预期长期盈利增长率 | 未来 3~5 年一致预期净利的 CAGR | 需**卖方分析师一致预期**（朝阳永续 / Wind consensus） |
| 盈利预期因子 | 一致预期的**调整方向与离散度**（上调家数占比 / 预期标准差） | 需**卖方分析师一致预期**（朝阳永续 / Wind consensus） |
| 预期市盈率 | totalmv / **未来 12 个月一致预期净利** | 需**卖方分析师一致预期**（朝阳永续 / Wind consensus） |

🔴 **`raw/jq/stk_fin_forcast.parquet`（124,083 行）不能顶替。** 它是**上市公司自己发的
业绩预告**（`profit_min` / `profit_max` / `type` 预增预减）：区间不是点估计、只在触发披露
阈值时才有、更新频率与覆盖率都不同。拿它当一致预期是「有值但对不上」——
比没有值更危险（同东财 f133 那个股息率：8 只里 7 只对、招商银行差一倍）。

⚠️ **连带影响两个 B 类因子**：Barra 的 `成长因子` 含 `EGIBS`、`收益因子` 含 `EPIBS`，
都是预期描述子 —— 本地只能做它们的**非预期部分**，那已经不是原来那个因子了。

### 合成风格因子（31 个）—— 缺的是**规格不是数据**

一个因子 = 若干描述子按权重合成 → winsorize → 标准化 → **对市值与行业正交化**。
这四件事聚宽都没公开完整规格。下表给的是 **Barra CNE5 的公开定义**，可以直接用，
但**算出来的值与聚宽的同名因子不可比** —— 同「对数对得上 ≠ 移植忠实」那条：
基准收益、beta、波动率这类只取决于数据与撮合的量会先对上，把人骗过去，而因子本身是错的。

| 动量因子 | RSTR = Σ<sub>t−504…t−21</sub> w<sub>t</sub> · ln(1+R<sub>t</sub>)，半衰期 126 日；**跳过最近 21 日** |
| 非线性市值因子 | NLSIZE = SIZE³ 对 SIZE 做横截面 OLS 取**残差**，再 winsorize + 标准化 |
| 市值立方因子 | SIZE³ |
| 中等市值因子 | −\|z(SIZE)\|　（离市值中位越近越大） |

| 市值规模因子 | 同 SIZE |

## 实现成本（实测，M4 / 12 核 / 24 GB）

| | 耗时 | 产出 |
|---|---:|---|
| 每日增量：算当天 216 个因子 | **3.4 s** | 216 行评价值 / 约 30 KB |
| 全历史重建评价序列（2003~2026） | **246 s** | 1,230,311 行 / **31.7 MB** |
| 六个 horizon × 216 因子 汇总 | **0.01 s** | 1,296 行 |

🔴 **两个实现陷阱，各差两个数量级**：

1. **评价层必须转长表**：216 个 `rank() OVER (PARTITION BY date ORDER BY <各自的列>)` 是
   **216 次独立排序**，DuckDB 无法共享 —— 733.6 s/年；`UNPIVOT` 成 `(date, factor, value)`
   后一次复合键排序只要 **12.6 s/年**（**58 倍**）。
2. **EMA 族必须出 SQL**：EMA/MACD/TRIX/RSI(Wilder)/KDJ 是递推的，窗口函数做不了。
   6 列全历史：纯 Python **40.19 s** ｜ pandas `groupby.ewm` 3.02 s ｜ **numba 0.37 s**（**108 倍**）。
   ⚠ `groupby.transform(lambda: x.ewm(...))` 会退回逐组 Python，**不要用**。

★ **因子值面板（7.6 GB）不用存** —— 它是中间产物，算完 IC/分位就能扔；重建只要 4 分钟，
  而存着的那份每次改口径（前瞻窗口 / rank IC vs 普通 IC / 股票池）就整份作废。
  要存的是**评价序列** `(date, factor, n, ic, q1, q10)`，31.7 MB 管全历史。

⚠️ **IC 要未来收益，所以评价序列天然滞后**：今天 09-22 跑，能结算的是 **08-25**
（20 个交易日前，`fwd20` 刚满）。想缩短滞后就换短周期前瞻，那是**口径选择**不是工程问题。
