# 索引 4 — 按陷阱（按失效模式倒查）

「结果不对但不报错」时查这里。**按错法分类，不按数据源分类** ——
因为你遇到症状时并不知道是哪个源的问题。

---



## `volume` 的单位在 2010-09 前后不同 —— 换手率大 100 倍而不报错

**失效模式**：`mart/panel_daily` 里 **2003-01 ~ 2010-08 的 `volume_shares`
与 `turnover` 大 100 倍**（254.7 万行）。表现是 2005 年中位换手率 **94.96%**、
2008 年 **167.11%** —— 数字荒谬但**没有任何报错**，而且 2011 年之后完全正常
（1.07~3.66），所以只看近期数据永远发现不了。

**判据**（`volume_shares` 应 ≈ `amount / close_bfq`，差的只是均价 vs 收盘价）：

```sql
SELECT strftime(date,'%Y-%m') ym,
       median(volume_shares / nullif(amount/nullif(close_bfq,0),0)) r
FROM read_parquet('mart/panel_daily/panel_*.parquet')
WHERE volume_shares>0 AND amount>0 AND close_bfq>0 GROUP BY 1 ORDER BY 1
-- ≈100 -> 2003-01~2010-08（2,547,360 行）
-- ≈1   -> 2010-09~2026-09（13,706,133 行）
```

**成因**：通达信 `.day` 里 `volume` 的单位在 2010-09 前后不同，而 `turnover`
是 tdx2db 用 `volume / 流通股数` **算**出来的，`load_tdx_kline.py` 又把
`raw_basic_daily` 原样拷进 `raw/tdx/basic`。

**影响范围（2026-09-03 逐个查过，目前为零）**：引擎的成交量约束刻意用
`amount`（元）绕开了单位陷阱；两条实盘线（froec / 红利指数增强）
grep `turnover`/`volume` 计数为 0；`sgmspeg` 用 `turnover_volatility`
但 69 次归档全部始于 2016。**将来跑 2010-09 之前的回测、且用到这两列时会踩。**

### 同一件事的另一面：重建一次，turnover 全程差 100 倍

    生产库（老 vipdoc 多年累积）  volume = 真实股数 × 100  -> turnover 是百分数
    新库（hsjday.zip 现在下的）    volume = 真实股数        -> turnover 是小数

实测：最近 250 天 861,032 行，`turnover` 中位 旧 **2.34** / 新 **0.0234**，
比值 **99.999**。

🔴 **行数一行不少，是【值】变了** —— 所以只查行数的缩表护栏拦不住它。
`datalake/setup_tdx.py` 另有 `_check_scale()`：拿两边重叠的最近 250 天比
`turnover` 中位，偏离 1 超过 5 倍就拒绝替换。
**"结构没变 + 行数没少"不等于"口径没变"。**

## 同一次分红，两个源的【标注不一样】—— 按单键去重会双计

**失效模式**：把外部分红明细（东财 `RPT_SHAREBONUS_DET`）与本地
`std/dividend.parquet`（聚宽）合并时，同一次分红被拆成两条，
年度合计凭空变大，**而它不报错** —— 只是股息率虚高、买点目标价算高。

两处实测（2026-09-03）：

| | 本地（聚宽） | 东财 | 差在哪 |
|---|---|---|---|
| 长江电力 0.21 元 | 报告期 **2024-09-30**、公告 2024-12-14 | 报告期 **2024-06-30**、公告 2024-12-14 | **报告期**标注不同 |
| 东阿阿胶 1.3448 元 | 报告期 2026-06-30、公告 **2026-08-21**（中期董事会预案） | 报告期 2026-06-30、公告 **2026-04-25**（年报里先披露的计划） | **公告日**标注不同（差 4 个月） |

按报告期去重 → 长江电力 FY2024 从 0.943 变 **1.153（+22%）**；
按公告日去重 → 东阿阿胶 2026 中期变两条。

**判据（`alerts._merge_rows`，三条任一命中即同一次）**：
① `(报告期, 每股金额)` 相同 ② `(公告日, 每股金额)` 相同
③ `公告日` 相同、金额不同 → 同一次但金额在实施时被修正，取进度更靠后那条。
两边都有时**留本地的报告期**（本地那份与 QMT `get_divid_factors` 12/12、
与手填 8/8 对过账）。selftest 里两条实测都钉死了。

★ 相关：外部缓存**不写进 `std/`**（那是 loader 链的产物），落
`datalake/rt/div_ext.json`；`_agg` 先按 as-of 砍掉公告日晚于当日的行 ——
缓存是"今天"抓的，而 as-of 可以往回问，不砍就是未来函数。

## 🔴 外部行情接口：**静默限流**（不是报错）

连打十几次东财 `push2his` 之后，**连 TCP 都不给**（`RemoteDisconnected`），
而且编号子域 `33./63.push2his` 是同一套限流、一起挂；只有
`push2delay.eastmoney.com` 还通。等 45 秒不恢复。
有时**不断连而是返回 `data: null`** —— `json.loads` 成功、`data` 是 `None`，
不小心就当成"这只票没数据"。

新浪的上限超了也是**静默给空**：`datalen>1023` 返回 `null`、多 `symbol` 返回 `null`。

★ 所以外部接口**一律要把"空结果"当失败处理**，不能当"没有数据"。
完整对照与可直接抄的调用见 **索引 5「外部行情接口」**。

## A. 静默返回空 → 策略照跑，只是一只票都选不出来

**最危险的一类：没有异常、没有日志、回测正常出报告。**

| 触发 | 症状 |
|---|---|
| QMT `report_type` 传 `'announce'`/`'report'`/`'1'`/`'0'` | 返回 `None`，财务整片为空 |
| QMT 财务日期带横杠 `'2024-01-01'` | 全 NaN |
| QMT 财务表名非全大写 | 全 NaN |
| QMT `ASHAREFINANCIALINDICATOR.*` | 全 NaN（**表不存在**） |
| QMT 行业名不带前缀（`'银行'`） | 返回 `[]` |
| QMT `THY1*` / `TGN*` 板块 | 返回 `[]`（本环境无成分数据） |
| QMT `'ST板块'`/`'ST'`/`'风险警示'`/`'*ST'` | 返回 `[]`（正确名字是 `'沪深风险警示'`） |
| 行业黑名单某项没匹配到板块 | 选股池多一批本该剔除的票，收益悄悄漂移 |

**防法**：这类只能靠**断言 + 显式告警**。移植里已做：
`_call_fin` 走降级阶梯并打印采用了哪种形态；`_resolve_industry_sectors` 对未匹配的行业
打 `[warn] 过滤【未生效】`；策略入口有 `_verify_fin_fields` 自检。

## B. 静默返回错值 → 数字看着完全合理

| 🔴 **同一个 CSV，三个解析器三个答案，其中两个不报错** | `raw/jq/_ingest/downloads/stk_fin_forcast.csv`（业绩预告）的 `content` 是大段中文正文，含换行、含**千分位逗号**，且有 **10 条记录引号未闭合**（上游写坏的）。后果：<br>· `csv.reader` → **50,650** 行（从未闭合的引号处开始把后续记录吞进同一字段）<br>· `pandas.read_csv` → **124,094** 行，**不报错**，其中 **11 行是垃圾**（`id` 列装着正文碎片、`code`/`pub_date` 全 NULL）<br>· DuckDB `read_csv_auto` → 直接报 `state machine reached an invalid state`（而 merge 脚本的 per-file try/except 会把整张表跳过，"预告没更新"只在日志留一行）<br>· 权威条数 **124,083**（`build/csv_repair.py`：按 `^\d+,\d+,\d{6}\.XSH[EG],` 判记录头 + 按位置切前 15 个字段 + 内容校验）<br>**判据**：多解析器交叉验证比单个解析器的"成功"可信得多 |
| 🔴 **「行数对上了」不等于「读对了」** | 上面那 11 行垃圾静默进了 `stk_fin_forcast.parquet` 并存活一周 —— 因为 `load_jq_round3.py` 当初只校验「落盘行数 == pandas 读入行数」，**两边一样错，检查照样通过**。现在改成校验【内容】：`id` 是纯数字、`code` 形如 `NNNNNN.XSHE/G`、`end_date`/`pub_date` 是日期。<br>那两个日期列的校验同时也是「按位置切前 15 个字段」这个做法的**证明** —— 若某条记录前 15 段里混进逗号，字段会整体右移，日期列必然对不上 |
| 记录头判据不能只看"数字开头" | 第一版判据是 `^\d+,`（行首数字加逗号），但 content 里有千分位逗号（`633,969.04元`、`1,606,637.86元`），这类续行被误判成新记录、字段整体错位，实测踩到 4 条。改成 `^\d+,\d+,\d{6}\.XSH[EG],`（id, company_id, 带后缀的 code）—— 正文续行不可能长这样 |

| 触发 | 错在哪 |
|---|---|
| `net_profit_this_year / total_owner_equities` 当 ROE | **分子归母、分母全口径**，差约 5%。这就是 L2 规范视图存在的理由 |
| 聚宽 `indicator.eps` 当**累计**用 | 误剔股票：603029 在 2018 累计 Q3 −0.05（剔），单季 **+0.02**（放行） |
| 聚宽 `indicator.roe` 分母当**期末净资产** | 命中率从 87.35% 掉到 41.22%，选股命中率只能到 72.1% |
| 聚宽 `indicator.roe` 忘了转小数 | 百分数当小数用，差 100 倍 |
| 聚宽 `volume` 当股数 | 差 100 倍 |
| `bonus_ratio_rmb` 忘了 ÷10 | 分红差 10 倍 |
| QMT `UpStopPrice`/`DownStopPrice` 当历史涨跌停价 | 是**实时值**：2026-08-30 跑、查 2025-06-30，601398 返 8.60/7.04 而实际 8.25/6.75；300750 返 447.60 而实际 301.19 |
| QMT 毫秒戳用 `utcfromtimestamp` | **差一天** |
| 混用 `share_rmb` / `share_trade_total` | A+B、A+H 公司流通股本不等（3.75% 量级） |
| 财务不过滤 `report_type = 0` | 混入母公司报表：平安银行 2015 合并营收 961.6 亿 vs 母公司 734.1 亿，净利差 10% |
| 用 2003 年前的聚宽财务 | `pub_date` 是假值（占位率 0.38~1.00） |
| `get_all_securities` 不传 `date=None` | **漏退市股** → 生存偏差 |
| 用当前股票名而非名称历史表 | 改名股对不上 |
| **直接用 QMT 的成品比率**（`du_profit_rate` / `adjusted_net_profit_rate`） | 用 QMT **自己的**原值复算，**3/4 命中 1/4 不命中**：601398 2024 全口径同比 +0.5012% == QMT 0.5012% 精确，但 601398 2023 归母 +0.9737% / 全口径 +1.1295% / 混口径 +0.8185% 三个候选**一个都不等于** QMT 报的 0.8301%，来源不明。→ 用 `ASHAREINCOME` 原值 + `m_timetag` 自己算（原值与本地 **8/8 精确吻合**，比率没有） |
| 把 QMT 的增长率当**单季**同比 | QMT 是**累计同比**，本地 `inc_*` 是**单季同比**。601398 2024 累计 0.50% vs 单季 1.35% —— 直接替换会让筛选结果**悄悄是错的** |
| 扣非 EPS 查单日 | 覆盖稀疏（57/244 交易日），单日大概率 NaN；且末个非空**可能不是最新报告期** → 要用 `m_timetag` 确认是哪一期 |
| **用 `get_financial_data` 的 Method2 判「字段是否存在」** | 🔴 **判不准**。`nan` ≠ 字段不存在，两个实测反例：`adjusted_earnings_per_share` Method2 返回 `nan` 但 Method1 有值 **0.97**；`ASHARECASHFLOW.dividend_interest_payment` Method2 `nan` 但中文写法 Method1 **非空 843 个** |
| **拿 Method2 的返回值当数值用** | Method2 与 Method1 取的**不是同一报告期**：`s_fa_bps` 9.55 vs 5.46、`du_return_on_equity` 10.037 vs 3.7869、`s_fa_eps_basic` 0.98 vs 0.21。Method2 只适合快速探路，取值一律用 Method1 + `m_timetag` |
| **`PERSHAREINDEX` 的金额类字段** | 🔴 `inc_revenue` / `inc_gross_profit` / `inc_profit_before_tax` / `du_profit` / `inc_net_profit` / `adjusted_net_profit` **值恒为 0**（不是 NaN，是 0，所以「非空检查」也拦不住）。金额一律去三大报表取 |

| `previous_date` 写成 `current_date` | 代价见 `assay/strategies/_demo/lookahead.py` |

## D. 口径差（两边都没错，只是定义不同）—— 不是 bug，但必须知道

| 项 | 差异 |
|---|---|
| 流通股本两定义 | `share_rmb`=流通A股 vs `share_trade_total`=流通股总计（含B/H） |
| 总股本 tdx vs 聚宽 | tdx 更符合会计口径（70.6% vs 29.4%） |
| 股本生效时点 | tdx 比聚宽**晚 1 个交易日**，边界日选股差一只，**本地无法消除** |
| 申万 2014 版 vs 2021 版 | 采掘→煤炭+石油石化；金融服务→银行+非银金融；**交运设备无法对应** |
| 聚宽选股/过滤混用两个日期 | 选股 `date=yesterday`、过滤 `get_current_data()` 取当日。**复现时必须照抄** |
| 业绩快报 vs 定期报告 | 聚宽 `pub_date` 99.8% 对齐定期报告 → 它自己也不用快报。快报数值口径可能不同（未审计），**不与主表混用同一 as-of** |
| 滑点口径 | 只有对标聚宽才设 0，否则**一律用默认值**（见 memory `backtest-cost-default`） |
| 🔴 **beta：本地原始 vs 聚宽标准化快档** | 本地 `std/beta_daily.parquet` = 沪深300、252 行**等权 OLS 原始值**；聚宽 `get_factor_values(['beta'])` = **标准化后的因子暴露**（2026-08-31 全市场 5212 只实测：横截面 std=**1.0000**，所以平安银行是 −1.57 这种值，不是原始 CAPM beta），且是**快档**（池内 Spearman 在半衰期 32~63 天最高 0.964~0.969，向等权单调降到 0.933）。用真值给红利 A 池（332 只）排序 **10/10 精确复现聚宽清单，连顺序都一样** —— 选股差异完全由此解释。但**业绩几乎打平**（2019-01~2026-08：聚宽 23.80%/回撤 13.83% vs 本地等权 24.41%/13.07%），**没有证据说哪边更好** |
| PE 阈值擦边 | `pe_ttm` 两边算法略有差别，卡绝对阈值时边界票会翻转。实测新华保险 2026-08-31 本地 `pe_ttm=5.0822` vs 阈值 `pe_lo=5.0`，**只富余 1.6%** → 聚宽侧掉出池子，Sleeve B 差一只 |
| 分位切点擦边 | 排序名次紧贴切点时，池子大小 `n` 差几只就翻转。实测永臻股份 2026-08-31 `rn2=156`、切点 `floor(0.1*1629)=162`，**只差 6 个名次** → froec 10 只里的最后一只两边不同 |

## E-0. 🔴 数据新鲜度错配 —— 行情补了，财务没补

补充（2026-09-01）：**三大报表此前完全没被监控** —— 实测卡在 2026-08-24 而指标已到 08-31，差 5 个交易日，没有任何地方会说出来。现已纳入 `build/sync_status.py` 的 B 腿（另加业绩预告）。
两条实盘策略（红利指数增强 / froec_traded）只用 `t_indicator` / `t_dividend` / `t_beta` / `t_universe`，**不碰三大报表**，所以这次滞后没影响实盘；但 `红利价值.py` 与 `build_jqfactor_q.py` 用，那条线会静默受影响。


**症状**：策略选出的票与聚宽对不上，而且对不上的那些**基本面阈值刚好卡在边界**。

**实例**（2026-09-01 实测）：行情补到 08-31，但 `raw/jq/fundamentals_indicator_q.parquet`
抽取于 **08-26**。2026 中报法定截止日是 **8-31**，08-27~08-31 正是披露高峰
（本地已有的分布：08-25 有 631 家、08-26 有 668 家）——
**本地 2026 中报只覆盖 55.6%（2892/5206）**。

后果：froec 的 `eps > 0` 过滤在两边用了**不同报告期**

| | 用的报告期 | 庄园牧场 eps |
|---|---|---|
| 本地 | 2026-03-31（Q1） | **−0.1611** → 被剔除 |
| 聚宽 | 2026-06-30（中报） | 已发布 → 保留 |

froec_traded 同日对比只有 **6/10 重合**，JQ 独有的四只里**三只**是这个原因
（庄园牧场 −0.1611 / 莎普爱思 −0.0698 / 汉商集团 −0.0185）。

**怎么发现**：对不上的票逐个看 `pub_date` 与 `report_date`。
若本地最新报告期比"当前日期该有的"落后一期，就是这个问题，不是逻辑差异。

**怎么修**：财务抽取脚本要在**聚宽研究环境**跑（本地跑不了），
`raw/jq/_ingest/extract_jq_*.py` → 下载 → `build/load_jq_*.py` → `build_panel_daily.py`。

**教训**：`tdx.db` 补行情和聚宽补财务是**两条独立的链路**，
补了一条不代表另一条也新。**面板的 `date` 到 08-31 不等于财务也到 08-31。**
排查跨源差异前，先核对**两条链路各自的最新时点**。

## E. 数据缺陷（已知、有边界）

## F. 工程陷阱（本项目踩过）

| 项 | 代价 |
|---|---|
| `io.open(p,'wb')` 写 GBK | **先截断再 encode**，encode 抛异常就留下 0 字节文件。必须**先 encode 再写** |
| GBK 文件声明 `#coding:gbk` 但实际是 UTF-8 | QMT 里 SyntaxError。`qmt/check.py` 已强制校验 |
| GBK 编不了 emoji（`⚠ ✔ ✅ 🔴`） | 改用 `[!] v [OK] [!!]` |
| zsh 不做变量分词 | 别用变量拼命令行参数，会**静默给出无效结果**（见 memory `zsh-no-word-split`） |
| `not r` 判空 pandas Panel | 抛 *The truth value of a Panel is ambiguous* |
| QMT 的 `print` 是缓冲的 | 一处卡死整轮无输出。所有接口调用必须包 `_call_timeout` |
| 补丁插到函数中间 | `ast.parse` **会通过**（孤立的 body 挂到下一个函数上）。改完必须跑等价性回归（equity 曲线 SHA256） |
| argparse `parents` + 全局选项 | `--runs` 放在子命令前会被**静默忽略**。用 `default=argparse.SUPPRESS` |
| 空仓/低仓位时仍出报告 | 实测过一次 8 年空仓仍给出「年化 10.85%」。`metrics.py` 已加仓位告警 |

## G. 方法论错误（最贵的教训）

| 🔴 **用有噪声的重建做单变量隔离，测出来是噪声** | 想量化「聚宽 beta vs 本地 beta 值多少」，我自己按文档重建了半衰期 63 天的 beta，同引擎只换这一项，得到「本地等权胜 6/8 年、+4.95pp/年、t=2.51、p=0.040」，并据此建议实盘用本地。**全错。** 拿聚宽真值一对：我任何一档重建给 A 池排序都只能复现 7~8/10，真值是 10/10 —— 那 5pp 差全在**重建误差**里，不是口径差异。逐年 t 检验、Wilcoxon、单调性扫描（32/63/126/252/504/等权 年化 19.11→24.41 单调）**全都煞有介事地成立**，因为它们一致地度量了同一个偏差。<br>**判据**：要隔离一个**外部**口径，必须先拿真值对数（本项目纪律第 3 条：探针只做验证，且带已知真值当场对数）。统计显著 ≠ 测对了东西 |

| 错误 | 代价 |
|---|---|
| **猜接口名，猜不中就断言「没有」** | 四条「取不到」全是错的。正解是 `dir(C)` 先枚举 —— 115 个成员一列就完 |
| **只请求业务字段却抱怨拿不到日期** | 只请求 4 个字段当然只返回 4 列。公告日一直都有 |
| **能查文档的却用探针穷举** | 试 18 个行业名全 0，而文档一句话说清「前缀+行业名」。**凡是能查到文档的，不要用探针去发现** |
| **把候选挂在不存在的表上** | 6/8 个扣非候选挂在 `ASHAREFINANCIALINDICATOR`，全 NaN 与字段名无关 |
| **信文档不验证** | 文档说 `report_type` 默认即 `announce_time`，**实测不传就是未来函数** → 查文档也要验 |
| 全程回测切片比对逐年差异 | 零触发年份也能差 8.42pp —— 测的是路径混沌不是规则。必须**逐年独立回测**（每年重置本金） |
| 用均值 t 检验评价尾部保护 | 尾部保护要分开看**保费**与**赔付**，均值检验是错的尺子 |
