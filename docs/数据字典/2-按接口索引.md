**`get_financial_data` 的三条红线：**

1. 🔴 **必须显式传 `report_type='announce_time'`**。601398 净利实测：

   | 日期 | `announce_time` | **不传** | `report_time` |
   |---|---|---|---|
   | 20241230 | 2.6902e+11 | 2.6902e+11 | 2.6902e+11 |
   | **20241231** | **2.6902e+11** ✅ | 3.6586e+11 | 3.6586e+11 |
   | 20250328 | 2.6902e+11 ✅ | 3.6586e+11 | 3.6586e+11 |
   | 20250331 | 3.6586e+11 ✅ | 8.4156e+10 | 8.4156e+10 |

   **不传 == `report_time` == 未来函数**（提前 88 天）。官方文档写的「默认即 `announce_time`」**与实测不符**。
2. 🔴 传 `'announce'`/`'report'`/`'1'`/`'0'` → **静默返回 `None`**，不报错 → 财务整片为空、策略照跑、一只票都选不出来。整数 `1`/`0` 有数据但语义未验。
3. 🔴 日期必须 `YYYYMMDD` 且 start/end 必传（带横杠全 NaN、不传报 TypeError）；表名必须**全大写**。

### xtdata / xtquant

`import xtquant` **成功**，`get_sector_list`/`get_stock_list_in_sector`/`download_sector_data`/
`get_financial_data`/`download_financial_data`/`get_instrument_detail` 六个函数都在。

🔴 但**连不上**：报的是**连接错误不是导入错误**。xtdata 是独立客户端，要连 QMT 数据服务端口
`58610`，完整版 QMT 里该接口默认不一定开，且调用前必须先 `xtdata.connect(ip, port=58610)`。
文件就在完整版目录 `D:\国金证券QMT交易端\bin.x64\lib\site-packages\xtquant\xtdata.py` ——
**xtquant 不是 miniQMT 专有**。

→ **策略移植一律走 ContextInfo**，用不到它。xtdata 只在「批量导出数据给 datalake」时才需要。

## 聚宽 JQ

| 接口 | 坑 |
|---|---|
| `get_fundamentals(query(...), date=)` | 🔴 必须过滤 `report_type = 0`（合并报表）。不过滤会混入母公司：平安银行 2015 年报合并营收 961.6 亿 vs 母公司 734.1 亿，净利差 10% |
| | 🔴 起点须 **≥2003**：1989–2002 的 `pub_date` 占位率 0.38~1.00 是假值 |
| | ⚠️ 返回的季度财务是**单季度**，不是累计 |
| `get_fundamentals(statDate=)` | ⚠️ 同一 `(code, statDate)` **只返回一条，没有修订史**。修订史走 `finance.STK_*` |
| `get_history_fundamentals(fields=[indicator.*])` | 与 `get_fundamentals(query(indicator))` **同源同口径** |
| `get_all_securities` | 🔴 必须 `date=None`，否则**漏退市股** |
| `get_factor_values` | 各因子确切定义见 `../jqfactor-口径.md`。⚠️ `PEG` 在盈利增长为负时返回 **NaN** 不是负值 |
| `get_current_data()` | ⚠️ 取**当日**数据。聚宽策略里选股用 `get_fundamentals(date=yesterday)`、过滤用它 → **混用两个日期**，复现时必须照抄 |
| `finance.STK_CAPITAL_CHANGE` | 两个流通股口径，见索引 3 |
| `finance.STK_XR_XD` | 分红必须用**公告日** |
