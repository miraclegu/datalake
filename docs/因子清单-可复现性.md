### B1 三个增长率 —— **已实测失败，不是没试过**

| 因子 | 结论（出处 [jqfactor-口径.md](jqfactor-口径.md)） |

## 另外两条口径提醒（数据在，但常数/复权要自己定）

- **夏普比率（20/60/120 日）本地没有无风险利率序列** —— 用 0 还是 0.04/252 结果不同。
  公式与数据都有，只是这个常数要先定下来并写进注释。
- 🔴 **技术指标一律用后复权**：`panel` 里 `open/high/low/preclose/close_bfq` 是**不复权**，
  只有 `close_hfq`/`hfq_factor` 是后复权（索引 3「行情组的复权口径不是一致的」）。
  `high_hfq = high × hfq_factor`。同一行混用不报错 —— 只是价格错一个复权因子，老股能差几十倍。
- `panel.turnover` 是**百分数**（`0.0883` = 0.0883%），与同一张面板里的 `roe_ttm` 等**小数**
  比率混着放。当小数用差 100 倍且不报错（索引 3「单位与标尺」）。

## 附：冒烟判据 SQL（复现上面那三行数字）

```sql
-- ① 量价类：20 日换手/换手比/乖离率/CCI 典型价/收益标准差/对数市值
WITH b AS (
  SELECT jq_code, date, close_hfq,
         high*hfq_factor AS high_hfq, low*hfq_factor AS low_hfq,
         volume_shares, amount, turnover, totalmv
  FROM read_parquet('mart/panel_daily/panel_*.parquet')
  WHERE date > DATE '2026-09-22' - INTERVAL 400 DAY AND date <= DATE '2026-09-22'
    AND public_status IN ('正常上市','ST','*ST')
), r AS (
  SELECT *, close_hfq/lag(close_hfq) OVER (PARTITION BY jq_code ORDER BY date) - 1 AS ret
  FROM b
), w AS (
  SELECT *,
    row_number() OVER (PARTITION BY jq_code ORDER BY date DESC) rn,
    avg(turnover) OVER (PARTITION BY jq_code ORDER BY date ROWS  19 PRECEDING) tr20,
    avg(turnover) OVER (PARTITION BY jq_code ORDER BY date ROWS 119 PRECEDING) tr120,
    avg((high_hfq+low_hfq+close_hfq)/3) OVER (PARTITION BY jq_code ORDER BY date ROWS 19 PRECEDING) tp20,
    avg(close_hfq) OVER (PARTITION BY jq_code ORDER BY date ROWS 19 PRECEDING) ma20,
    stddev_samp(ret) OVER (PARTITION BY jq_code ORDER BY date ROWS 19 PRECEDING) sd20
  FROM r
)
SELECT count(*) n, count(tr20), count(tr20/nullif(tr120,0)),
       count(ma20/close_hfq-1), count(tp20), count(sd20), count(ln(nullif(totalmv,0)))
FROM w WHERE rn = 1;
-- 5236 只，六列全部非空

-- ② 财务类：as-of 按 pub_date 可见
WITH bal AS (
  SELECT code, total_liability, total_assets, capital_reserve_fund,
         paidin_capital, total_owner_equities
  FROM read_parquet('raw/jq/financials/balance.parquet')
  WHERE pub_date <= DATE '2026-09-22'
  QUALIFY row_number() OVER (PARTITION BY code ORDER BY report_date DESC, pub_date DESC)=1
), cf AS (
  SELECT code, net_operate_cash_flow
  FROM read_parquet('raw/jq/financials/cashflow.parquet')
  WHERE pub_date <= DATE '2026-09-22'
  QUALIFY row_number() OVER (PARTITION BY code ORDER BY report_date DESC, pub_date DESC)=1
), mv AS (
  SELECT jq_code, totalmv FROM read_parquet('mart/panel_daily/panel_*.parquet')
  WHERE date = DATE '2026-09-22'
)
SELECT count(*) n,
  count(total_liability/nullif(total_assets,0)),
  count(capital_reserve_fund/nullif(paidin_capital,0)),
  count(cf.net_operate_cash_flow/nullif(mv.totalmv,0)),
  count(mv.totalmv/nullif(total_owner_equities,0))
FROM bal JOIN cf USING(code) JOIN mv ON mv.jq_code = bal.code;
-- 5178 / 5178 / 5167 / 5178 / 5144
```

🔴 第 ② 条的 `QUALIFY` 里 **`report_date DESC` 必须排在 `pub_date DESC` 前面。**
只按 `pub_date` 排的话，**同一天公告多个报告期**时会挑到旧的那个 —— 实测
`(code, pub_date)` 有多个 `report_date` 的组合 **23,382 组**（年报与季报同日公告是常态），
两种排序在 2026-09-22 这个 as-of 上给出不同报告期的公司 **2,022 家**。**而它不报错。**
