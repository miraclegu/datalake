# 聚宽 jqfactor 口径 → 本地实现

> 建立于 2026-08-29。来源：`JQ/小市值/PROBE-因子口径验证{,-v2,-v3}.txt` 三轮探针
> 在聚宽平台上直接打印因子值 + 本地离线拟合。
>
> **为什么要有这份文档**：`get_factor_values('sales_growth')` 这种调用，名字看着
> 一目了然，实际定义可能和字面含义相差很远（`sales_growth` 甚至和 5 年营收 CAGR
> 的**秩相关只有 +0.49**）。口径猜错的后果不是差几个小数点，而是**选出完全不同
> 的股票**，且回测数字看着"挺接近"、不会引起怀疑。本项目已因此多次得出又撤回结论。
>
> **验收标准**：逐只精确匹配，不接受"接近"。相对误差 < 0.5% 才记为定案。
>
> **范围更广的那份清单**在 [因子清单-可复现性.md](因子清单-可复现性.md)：
> `factors.xlsx` 285 条按「能不能复现」分三类。本文件是其中**已定案那几个**的推导，
> 以及 `sales_growth` / `earnings_growth` / `operating_revenue_growth_rate`
> **为什么至今未定案**的证据。

## 方法：为什么用探针而不是用回测锚反推

聚宽侧有五个回测锚（v3d / solo-SG / solo-MS / solo-PEG / v0b），但**用 5 个聚合
指标反推 7 个因子定义是欠定的**——多组定义能给出同样的年化。而且每次迭代要跑一轮
完整回测。

正确做法是写只读探针在聚宽上跑，直接打印 `get_factor_values` 的返回值，
和本地候选公式逐只比对。先例：`JQ/小市值/PROBE-ROE口径验证.txt`（当初就是用它
确定 `indicator.roe` 的分母是**平均净资产**而非期末——本地曾用期末，
257,525 条比对只有 41.22% 吻合）。

**三轮探针的经验**（写下来免得重复）：

| 轮次 | 设计 | 结果 | 教训 |
|---|---|---|---|
| v1 | 候选公式**算在探针里**，只打"哪个命中" | `turnover_volatility` 一轮即中；其余全不中 | 有**强先验**时高效 |
| v2 | 改为**导出原始序列**，离线拟合 | 一轮解出 3 个 | 没先验时必须导出原始数据——"全不中"不提供任何线索 |
| v3 | 横截面 mean/std **判决性检验** | 排除了"标准化因子"假设 | 拟合不出来时，先用**分布指纹**缩小候选类别 |

探针必须**自报家门**：模块级 `print` + `initialize` 日志 + `before_open` 心跳 +
全身 `try/except` 打堆栈。v1 初版所有输出都在 09:31 的探测函数里、异常被吞，
结果是"点了运行什么都不打印，无法判断是否开始执行"。

## 一、机制性发现（这些是解开口径的钥匙）

### 1. 三个聚宽接口的累计/单季口径

README 已记录前两个，本次补第三个：

| 接口 | 口径 | 证据 |
|---|---|---|
| `finance.STK_INCOME_STATEMENT` | **累计**（年初至今） | 平安银行 2017 四期相加 ≈ 2.6× 年报 |
| `get_fundamentals(statDate=...)` | **单季** | 平安银行 2017 四个单季相加 == 年报，精确 |
| **`get_history_fundamentals(interval=...)`** | **单季** | 见下 |

`get_history_fundamentals` 返回单季值的两条硬证据：

```
证据1  000800 的 total_operating_revenue：2018Q1 = 7.15e9 > Q2 = 6.33e9 > Q3 = 5.55e9
       —— 累计值不可能递减
证据2  300028 的 2016-12-31 营收 = -2.91e5
       —— 累计年营收不可能为负（单季可以：退货/冲销）
```

### 2. `interval='1y'` 不是"年报"

它是**「每年同一报告期的单季值」**。`watch_date=2018-12-28, count=7, interval='1y'`
返回的 `statDate` 是 **2012-09-30 … 2018-09-30**（锚在最新可用报告 2018Q3 上），
**不是** 12-31。

> 最初按「累计 + 年报」计算，v1 探针的所有候选全不中，根因就在这两条。

### 3. TTM 同比的分母【不取绝对值】

```
TTM(t)   = 单季(t) + 单季(t-1) + 单季(t-2) + 单季(t-3)
TTM同比  = TTM(t) / TTM(t-4)  - 1        ← 分母取【原值】，不取 abs
```

判例 `300028`（连亏两年，分子分母同为负）：

| 分母取法 | 结果 | 聚宽实际值 |
|---|---|---|
| `abs(pre)` | −2.888508 | — |
| **原值 `pre`** | **+0.888508** | **0.888508** ✅ |

负÷负=正。不抓住这条就永远差一个符号，而且只在亏损股上暴露——用盈利股做样本
根本发现不了。

### 4. 净利润用【全口径】不是归母

`net_profit_growth_rate` 用 `income.net_profit`（含少数股东），
用 `income.np_parent_company_owners`（归母）作对照组是 **0/6**。

（但 `PEG` 里的 `pe_ratio` 用的**是归母** —— 同一策略里两个口径并存，
不能想当然统一。）

## 二、逐因子定案

窗口：决策日 2018-12-28，抽样 6~12 只跨市值分布。

### ✅ `turnover_volatility` — 换手率波动

| | |
|---|---|
| **定义** | `valuation.turnover_ratio` 最近 **20 个交易日**的标准差（`ddof=1`），**÷100** |
| **量纲** | `turnover_ratio` 是百分数，因子是小数 |
| **本地实现** | `stddev_samp(panel.turnover)` over 20 rows / 100（确认 `panel.turnover` 与 `turnover_ratio` 同源同量纲后可直接用） |
| **证据** | 300179: 0.504361/100 = **0.005044** = JQ 0.005044；600328: 0.272573/100 = **0.002726** = JQ 0.002726。另有 10/11 只用近似输入时比值精确 100.0000 |

> v1 用 `volume / 当期流通股本` 近似，`603679` 差 7%——因为它在窗口内有股本变动
> （次新解禁），固定分母不成立。**用 `turnover_ratio` 本身，不要自己算换手率。**

### ✅ `total_profit_growth_rate` — 利润总额增长率

| | |
|---|---|
| **定义** | **TTM 利润总额同比**，`income.total_profit`，分母取原值 |
| **本地数据** | `lake.db` → `fin_income.total_profit`（273,018 行，非空 **100.0%**，2003-03-31~2026-06-30）；规范层已暴露为 `fin_core.profit_before_tax` |
| **⚠ 派生层缺口** | `std/fin_quarterly.parquet` 当初只带了 `np_cum`/`rev_cum`，**没带 total_profit**，要用需补一列（不用重新采数） |
| **证据** | 6/6 精确（300028 靠"分母取原值"才对上） |

> **不能用营业利润代理**：`corr(营业利润, 利润总额) = 0.9995` 看着很高，但
> **利润总额 ≥ 营业利润的只占 61.1%**——39% 的样本营业外净额为负。而本因子是
> 按增长率**排序取前 10%**，排序对尾部差异极敏感。
> **高相关系数不是"可以代理"的依据。**

### ✅ `net_profit_growth_rate` — 净利润增长率

| | |
|---|---|
| **定义** | **TTM 全口径净利润同比**，`income.net_profit`（含少数股东），分母取原值 |
| **证据** | 6/6 精确；归母口径对照组 0/6 |

### ✅ `PEG`

| | |
|---|---|
| **定义** | `pe_ratio / (归母净利 TTM 同比 × 100)` |
| **其中** | `pe_ratio = market_cap / 归母净利TTM`（已独立验证：000800 = 107.74亿/1.251亿 = 86.12 vs 聚宽 86.1043） |
| **证据** | 4/4 精确（002377 517.6062 vs 517.6067；600328 24.1448 vs 24.1448；600239 140.1800 vs 140.1798；000800 137.7154 vs 137.7153） |
| **🔴 本地现有实现是错的** | `panel.peg = (totalmv/np_ttm)/(np_yoy*100)` —— `np_yoy` 口径不对（不是归母 TTM 同比），需按上式重算 |
| **覆盖率** | 800 只里只有 **398 只**有值（增长率为负或分母异常时为 NaN）。策略里 `positive_only=True` 会再筛一道 |

## 三、未定案

### 🟡 `operating_revenue_growth_rate` — 营收增长率（4/6）

TTM 营收同比中 4/6。已排除的解释：

- **不是字段选择问题**。试过 `income.operating_revenue`（营业收入）与
  `total_operating_revenue`（营业总收入）：`002377` 两者确实不同
  （`inc_revenue_year_on_year` 26.12 vs `inc_total_revenue_year_on_year` 26.35），
  但换用 `operating_revenue` 得 2.349 vs 聚宽 2.477，仍不中；
  而 `000800` 两个字段**完全相同**，它的缺口（TTM 得 +0.729% vs 聚宽 −1.5556%）
  与字段无关。

### ❌ `sales_growth` / `earnings_growth` — 5年营收/盈利增长率

**分布指纹（800 只横截面）**：

| 因子 | mean | std | min | max |
|---|---|---|---|---|
| `sales_growth` | −0.0253 | **0.204** | **−0.8686** | **+0.8258** |
| `earnings_growth` | +0.0225 | **0.352** | **−0.9938** | **+0.9123** |
| 三个 `*_growth_rate`（对照） | — | **1.25 / 18.8 / 6.2** | — | **25.9 / 486.9 / 43.5** |

**结论：不是标准化因子，是「有界」因子** ——
标准化的指纹是 mean≈0 **且 std≈1**；这两个 mean≈0 但 std 只有 0.20/0.35，
且严格落在 **(−1, +1)** 内。这同时排除了原始增长率（std 6~19、max 上百）**和**
标准化。剩余候选是形如 `(a−b)/(a+b)`、相关系数这类**天然有界**的构造。

**已排除的候选**（不要重试）：

| 候选 | 结果 |
|---|---|
| Barra SGRO/EGRO 式：5 财年每股/总额对时间回归斜率 ÷ 均值 | 0/6 |
| 5 年 CAGR、首末简单比 | 0/6 |
| 5 年 TTM 序列 + 回归斜率/均值（5 或 6 点，取/不取 abs） | 0/2 |
| 与时间的相关系数 | 符号相反 |
| `(TTM新−TTM旧)/(TTM新+TTM旧)` | 300179 −0.0911 vs −0.0947（差 4%）；600328 +0.0660 vs +0.0316（差 2 倍）——**方向对但不是它** |
| **离线网格穷举 300 组**（TTM/单季 × 3~6 点 × 步长 1/4 × 5 种偏移 × abs × log） | 最小误差 0.0226，且最优解是"用 2016Q3 结束的数据"这种无意义组合 |

**与 CAGR5 的关系**：皮尔逊 **+0.92** 但秩相关仅 **+0.49**、符号一致 5/10。
**高相关 + 低秩相关 = 同源但被某种非单调变换处理过。**

## 四、对实现的影响

**PEG 路现在可以精确实现** —— 它的三个输入（`PEG`、`turnover_volatility`、
`indicator.eps`）全部已定案。而 solo-PEG 的锚是 **23.08%**，比 v0b 基准 38.98%
**低 15.9pp**，是五个锚里鉴别力最强的（做错不可能歪打正着）。

所以实现顺序应为 **PEG 路 → 框架验证 → 再啃 SG/MS**：先用一条完全可复现的支线
验证三路框架（并集逻辑、`[:5]`/`[:15]` 切片、eps 过滤、市值排序），
框架确认无误后，即使 SG/MS 只能用近似因子，误差也被隔离在那两路内。

聚宽侧校验锚（窗口 2019-01~2026-06，滑点 0.0015 + 佣金万3 + 最低5 + 印花税千一）：

| 版本 | 年化 | 夏普 | 回撤 | 交易次数 | 换手 |
|---|---|---|---|---|---|
| v0b（无因子层） | 38.98% | 1.139 | 51.86% | 556 | 7.4 |
| solo-SG | 41.95% | 1.270 | 40.08% | 576 | 7.7 |
| solo-MS | 42.49% | 1.232 | 45.41% | 630 | 8.4 |
| **solo-PEG** | **23.08%** | 0.719 | 37.69% | 1102 | 14.7 |
| v3d（三路） | 48.27% | 1.445 | 43.22% | 817 | 10.9 |

> **交易次数与换手比收益更能鉴别选股口径** —— 它们直接反映候选池规模与
> 换仓频率，而年化会被区间红利掩盖。

## 五、顺带记录：MS 路的评分权重问题

`SG-MS-PEG-HL.txt` 第 77 行：

```python
df['total_score'] = 0.1*operating_revenue_growth_rate + 0.35*total_profit_growth_rate \
                  + 0.15*net_profit_growth_rate + 0.4*earnings_growth
```

**四个原始增长率直接加权求和、无归一化。** 实测（2019-09-30 横截面，3684 只，
三因子代理）：

| 因子 | 名义权重 | 原始标准差 | 实际影响力占比 |
|---|---|---|---|
| 营业收入增长率 | 0.10 | 9.7 | **1.4%** |
| 营业利润增长率 | 0.35 | 124.3 | **63.1%** |
| 净利润增长率 | 0.15 | 163.5 | **35.5%** |

总分排序与「营业利润增长率」排序的**秩相关 0.9825** —— 名义占 10% 的营收因子
实际几乎惰性。更糟的是**被极端值支配**：营业利润增长率 P99 只有 21.7 而最大值
**6312.8**；MS 路取前 10% 里有 **19.6%** 是增长率 >1000% 的票，前几名全是
「去年同期利润接近零」的除法产物（600336 营业利润 +631280%）。

聚宽作者自己在 v3b 注释里写了「**「未标准化就加权求和」这个更本质的问题留给 v4**」，
而 `SG-MS-PEG-HL-v4.txt`（MS 路改 `rank(pct=True)`）状态是**「待跑」**。

⚠️ 推论：JQ 那句「因子层价值几乎消失（后段仅 +1.9pp）」是在**这个坏实现**上测的。
它只能说明该 MS 实现失效，**不能说明成长因子失效**。要回答后者必须先归一化。
